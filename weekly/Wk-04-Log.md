# Week 4 log

I chose to gate each slice independently and compare it with the currently approved artifact. The alternative was to start with one overall mAP floor. That would have been easy to explain and stable when small slices fluctuate, but it would have hidden the failure this week was meant to catch. The normalization change moved overall mAP from 27.80% to 26.68%. In low light the drop was 10.42 percentage points. The same signed model package that looked close in the aggregate therefore stayed in published state.

The comparison only means something if both runs use the same inputs. I kept the twenty outdoor originals paired with their low-light, blurred, and noisy versions. The other positive slices use separate photographs, and the negatives have explicit empty labels. The exact label file names each source and pins the bytes of all 140 images. It also pins the annotation coordinates and version. The CPU result carries a benchmark profile, so a new model cannot pass a latency comparison by moving to a faster host. A baseline re-run is needed when the approved result cannot be compared on the current dataset and CPU.

I also separated the gate's decision from operator approval. I considered letting the runner patch the artifact directly after a passing evaluation. That would have left the operator and the runner with the same authority and made it harder to reconstruct why a bundle reached a robot. The registry now stores the submitted evidence and recomputes the decision. When the operator approves, it checks that decision again under the current policy and against the current approved artifact. Approval and the audit row commit together. In the local PostgreSQL and MinIO run, an enrolled Fari fetched a byte range of the approved baseline and received HTTP 403 for the failed candidate.

The most useful next input is a representative camera benchmark for the actual edge hardware. The current indoor photographs establish a household-object regression check with measurable labels. Their box area estimates range, and the synthetic negatives establish a repeatable false-positive check. The on-device agent still needs to enforce the safe update window and interaction state at activation time.
