# ADR-0001: Use Docker Compose locally and target Azure Container Apps

Status: Proposed - for Xiaoyu and mentor review  
Scope: Week 1 decision; cloud infrastructure implementation in Week 7

Choose Docker Compose for the local control plane: Python 3.11/FastAPI services, PostgreSQL, and MinIO. Week 1 starts only the empty registry and its dependencies; later Compose profiles can add the controller, observability, and 20 simulated agents across three sites. Those agents represent independent robot processes, so the programme's fleet target does not itself require Kubernetes scheduling. kind and k3d would provide Kubernetes APIs and useful cluster experiments, but would also introduce cluster networking, manifests, storage configuration, and an additional failure surface before the registry contract exists. They are rejected for this eight-week implementation because Rover's intermittent connectivity and Fari's update windows are agent/application responsibilities, not problems a local cluster resolves. Retain container images, explicit health checks, environment-based configuration, and persistent volumes as the portable units. Compose is an application model for services, networks, and volumes; local/cloud parity means matching contracts and failure behaviour, rather than claiming identical orchestration. See the [Compose application model](https://docs.docker.com/compose/intro/compose-application-model/).

For Week 7, target Azure Container Apps for the stateless registry and controller, PostgreSQL Flexible Server for relational state, and Azure Blob Storage for artifacts. Keep rollout state in PostgreSQL and use a database advisory lock for one active controller; do not rely on a single container replica for correctness. AKS remains the alternative if a demonstrated requirement needs Kubernetes APIs or cluster-level control; a VM would preserve Compose most directly but make host patching, process supervision, TLS, and recovery our responsibility. Container Apps provides managed container hosting without direct Kubernetes API access, which fits this small HTTP control plane; this is a design choice, not a cost guarantee. See [Microsoft's container-hosting comparison](https://learn.microsoft.com/en-us/azure/container-apps/compare-options). Terraform modules, sizing, minimum replicas, and sandbox cost measurement belong to Week 7. Azure apply requires an explicitly approved sandbox, budget alert, owner/env/expiry tags, and a destroy procedure; normal CI must not create chargeable resources. Revisit this ADR only if the 20-agent laptop test or a concrete hosting constraint fails, and record the evidence before changing the runtime. Basis: personal SDE plan Section 1.4 and pp. 5-7, 12, 14; mentor-confirmed Week 1 scope.
